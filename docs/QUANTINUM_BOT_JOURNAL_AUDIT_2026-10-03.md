## What the numbers do and do not say

- At the observed average win and loss sizes, the break-even win rate is about 31%. The observed 31% win rate and 1.01 profit factor leave almost no margin for option spread, fill error, or other costs. Raising win rate alone is not the objective; positive out-of-sample expectancy after realistic execution costs is.
- Do not treat the five open positions as wins or losses. Likewise, a published setup that has not triggered is a candidate, not a trade. The attached HON setup explicitly says “not triggered yet,” so it must not enter the Bot fill win-rate denominator.
- Keep the three runs separate. The older +$4,908 Run 2 currently masks the newer Run 3's −$4,529 result in the combined book.
- The paper ledger is the right source for bot fills, but it does not establish realistic option execution. Before changing stop/target rules based on P&L, audit each fill against the signal snapshot, contract bid/ask and quote age, entry/exit timestamps, exit reason, and a conservative fill model.
- Code inspection found execution-accounting mismatches: entries pay the ask (`server/quant-bot.ts`), but old delayed fallbacks could mark options at midpoint; several exit reasons used a cached mark without refreshing a sell-side quote. Normal Bot option entries and automated exits now require a non-delayed, timestamped, two-sided, uncrossed quote no more than 60 seconds old. Entries pay the ask; exits use the bid and record bid/ask/source/feed/delay/provider timestamp/age. Manual option closes now use this same fresh-bid path rather than the caller-supplied price. With no qualifying quote the entry is skipped or the position remains open. The paper-position insert now persists the entry audit text and signal set that its caller already supplied. The Alpaca adapter now tries latest OPRA quotes first, then falls back to indicative as a delayed display mark; OPRA 401/403 responses are cached briefly to avoid repeated denied requests. These code paths still need confirmation on a newly persisted fill; the running app was not restarted.

The configured Alpaca credentials were checked against its read-only latest-options-quotes endpoint on 2026-10-03. OPRA returned HTTP 403, `OPRA agreement is not signed`; indicative returned HTTP 200 but the latest quote timestamp was 2026-10-02 19:59:59Z. Because the market was closed at the time of this check and OPRA access is not enabled, this did not qualify as a live execution quote. Until the OPRA agreement/entitlement or another real-time provider is available, the new Bot execution gate will skip entries and leave exits open when it cannot get a fresh eligible quote. Expiry settlement remains a separate intrinsic-value process. Historical impact still cannot be reconstructed because prior paper rows lack quote provenance.
- NEXUS option expiry outcomes now use intrinsic value from the exact expiry-day underlying print, with the applicable AM/PM settlement field. If that print is unavailable, contract P&L is left null and excluded; an underlying percentage move can no longer stand in as a measured option outcome. Previously closed historical rows still need a separate data-backed regrade; this runtime fix does not rewrite them.
